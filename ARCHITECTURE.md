# Context File Maker — Architecture

Narrative system design. Canonical data-flow, privacy, and output rules live in `docs/DATA-CONTRACT.md`. Canonical field names live in `schemas/` and `docs/questionnaires/`.

## System Overview

```
User (any AI tool user)
        │
        │ "build my context files"
        ▼
┌───────────────────────────────────────┐
│  Context File Maker Agent             │
│  (Cursor custom agent / LLM prompt)   │
│                                       │
│  ┌─────────────────────────────────┐  │
│  │  Interview Engine               │  │
│  │  - Phase sequencing             │  │
│  │  - Adaptive follow-ups          │  │
│  │  - Response validation          │  │
│  │  - Progress tracking            │  │
│  └───────────┬─────────────────────┘  │
│              │                        │
│  ┌───────────▼─────────────────────┐  │
│  │  Template Engine                │  │
│  │  - Markdown template selection  │  │
│  │  - Field filling from answers   │  │
│  │  - Consistent formatting        │  │
│  └───────────┬─────────────────────┘  │
│              │                        │
│              ▼                        │
│  ┌─────────────────────────────────┐  │
│  │  Generated Context Files        │  │
│  │  about_me.md                    │  │
│  │  ai_preferences.md              │  │
│  └─────────────────────────────────┘  │
└───────────────────────────────────────┘
```

## Interview Flow — Free Tier

### about_me.md (4 phases)

```
Phase 1: Identity & Role (~60s)
  ├── Full name, preferred name
  ├── Role, company, company size
  ├── Industry, years experience
  └── → Phase 2

Phase 2: Work & Projects (~90s)
  ├── Primary work description
  ├── Current projects (top 1–3)
  ├── Biggest challenge (critical pain point)
  ├── Goals (6mo, 2yr)
  └── → Phase 3

Phase 3: Technical & AI (~60s)
  ├── Tech stack, languages, frameworks
  ├── AI tools used, proficiency
  ├── AI pain points
  ├── Favorite/avoided tools
  └── → Phase 4

Phase 4: Personal & Preferences (~30s)
  ├── Location, work hours, timezone
  ├── Communication style, learning style
  ├── Hobbies, fun fact (optional)
  └── → Generate about_me.md
```

### ai_preferences.md (5 sections)

```
Section 1: Communication Style (~30s)
  ├── Tone, verbosity
  ├── Explanation policy
  ├── Clarification policy
  └── → Section 2

Section 2: Code & Technical (~30s)
  ├── Comments, error handling
  ├── Testing policy, formatting
  ├── Naming conventions, patterns
  ├── Language/framework preferences
  └── → Section 3

Section 3: Workflow (~30s)
  ├── Approach (plan vs code-first)
  ├── Iteration style, file editing
  ├── Commit policy, documentation
  ├── Scope policy
  └── → Section 4

Section 4: Constraints (~30s)
  ├── Secrets handling
  ├── External services policy
  ├── No-touch files
  ├── Breaking changes tolerance
  ├── Dependencies policy
  └── → Section 5

Section 5: Pet Peeves (~30s)
  ├── Pet peeves
  ├── Past frustrations
  ├── Must-haves
  ├── Never-do
  └── → Generate ai_preferences.md
```

## Template Architecture

Templates are structured markdown with placeholder fields:

```
# About Me
*Generated by Context File Maker*

## Identity
- **Name:** {{full_name}} ({{preferred_name}})
- **Role:** {{job_title}} at {{company}}
...
```

The agent fills placeholders from interview answers. This ensures consistent output regardless of LLM variability.

## Agent Prompt Architecture

The LLM system prompt (`agents/context-file-maker-agent.md`) defines:

1. **Role** — Context File Maker identity and purpose
2. **Interview Protocol** — Phase sequencing, adaptive follow-up rules
3. **Template Filling** — How to map answers to template fields
4. **Guardrails** — Hard limits, decline rules, boundary enforcement
5. **Output Format** — How to present generated files to the user

## Cursor Integration

```
.cursor/
├── rules/
│   └── context-file-maker-core.mdc   # Auto-loads SOUL.md on workspace open
└── skills/
    └── context-file-maker/
        └── SKILL.md                  # Full execution sequence for the agent
```

The `.mdc` rule auto-loads and forces reading `SOUL.md` at session start. The SKILL.md defines the complete interview protocol.
